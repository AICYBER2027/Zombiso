# VicePulse: GTA short-form media engine

Turns gameplay footage that we own or have licensed in writing into five original short videos a day **per
language**, for **VicePulse EN** (English) and **VicePulse BR** (Brazilian Portuguese), and prepares them for
YouTube Shorts, Instagram Reels and TikTok. The plan behind it is in [PLAN.md](PLAN.md).

> **Status: built and tested locally only.** Nothing has been deployed, no account has been created, nothing has
> been published, no money has been spent, and no paid API has been called. In tests, Claude and all three
> platforms are replaced by offline fakes.

## Decisions currently in the code (all changeable)

| Decision | Current default | Change it in |
|---|---|---|
| Channels | VicePulse EN (`en`) and VicePulse BR (`pt-BR`), 5 clips a day each | `config/channels.json` |
| Commentary voice | The owner records each script. Until a recording exists, the clip renders with captions only. | `VICEPULSE_VOICE_MODE` (`own` / `none`; `synthetic` is a placeholder) |
| n8n | Self-hosted, queue mode | `docker-compose.yml` |
| Language | Stored on every clip; EN and BR scripts are written separately, never translated | `config/channels.json` |
| Claude | `claude-opus-5-5` for selection, commentary and the final check; `claude-haiku-5-5` for triage | `.env` |
| Game | `gta5` for testing; switch to `gta6` at launch | `VICEPULSE_GAME`, `config/games.json` |
| Brand in legal drafts | `{{BRAND}}` placeholders | `legal/` |

## Safety switches (safe by default)

| Setting | Default | Meaning |
|---|---|---|
| `LLM_MODE` | `mock` | `anthropic` makes real, **billed** Claude calls |
| `VICEPULSE_ALLOW_LIVE_PUBLISH` | `0` | Due posts become `dry_run` and nothing is sent. Even at `1`, each platform account row must also be `enabled` |
| `VICEPULSE_REQUIRE_APPROVAL` | `1` | A person approves every clip before it is scheduled |
| `platform_accounts.audited` | `false` | YouTube uploads private and TikTok posts `SELF_ONLY` until the owner marks the platform audit as passed |

## How it works

```
footage file ──► ingest + rights gate 1 ──► signals ──► triage (Haiku) ──► selection per channel (Opus)
   (own or licensed;      (fails closed)     (FFmpeg      + blocked-tag      + duplicate checks
    no downloading)                           scenes,       filter)
                                              loudness,
                                              Whisper opt.)
──► commentary EN / pt-BR (Opus) + script dedupe ──► FFmpeg render 1080x1920, burned captions, optional voice
──► final policy check (Opus) ──► human approval (incl. TikTok's per-post choices) ──► schedule
──► publish (rights gate 2 re-checked; dry run unless switched on) ──► analytics ──► feeds next selection
```

Every stage is a `vicepulse` CLI command that prints one JSON object. n8n calls them through a small
token-protected HTTP worker (`vicepulse serve`) inside the docker network.

| Folder | What is there |
|---|---|
| `src/vicepulse/` | The pipeline package (one module per stage; `platforms/` holds the YouTube, Instagram and TikTok clients) |
| `db/migrations/` | Postgres schema: channels, platform accounts, rights ledger, sources, candidates, clips, renders, publish jobs (unique per clip and platform), metrics, topics, creator prospects, audit events |
| `n8n/workflows/` | The ten workflows from PLAN.md 3.9, generated by `n8n/build_workflows.py` |
| `config/` | Channels and per-game rules (blocked spoiler tags) |
| `legal/` | Drafts: privacy policy, terms, creator footage licence, takedown procedure (**lawyer review needed**) |
| `approvals/` | Draft answers for the TikTok, YouTube and Meta reviews, and the owner checklist |
| `tests/` | Unit tests and the end-to-end dry run |
| `docker-compose.yml` | n8n (main + worker), Postgres, Redis and the VicePulse worker, for later use |

## Run it locally

Needs Python 3.11+, FFmpeg (with libass) and PostgreSQL 14+.

```bash
cd gta-media
python -m venv .venv && . .venv/bin/activate
pip install -e '.[test]'

# Tests: they start a throwaway Postgres if PostgreSQL is installed, or use TEST_DATABASE_URL
# (an empty database you don't mind wiping). They take about 5 minutes, mostly FFmpeg renders.
python -m pytest
```

Trying the pipeline by hand on your own recording (still offline: mock Claude, no publishing):

```bash
cp .env.example .env           # set DATABASE_URL; keep LLM_MODE=mock and VICEPULSE_ALLOW_LIVE_PUBLISH=0
set -a; . ./.env; set +a
vicepulse migrate
vicepulse rights-add --json '{"owner_name": "VicePulse", "licence_type": "own",
  "platforms": ["youtube","instagram","tiktok"], "starts_on": "2026-11-10",
  "monetisation_allowed": true, "derivative_edits_allowed": true}'
vicepulse rights-verify --id 1 --by "your name"
vicepulse ingest --file ~/recordings/session1.mp4 --origin own_recording --rights-id 1
vicepulse signals
vicepulse daily                 # select + script + render + check, for EN and BR
vicepulse queue                 # what is waiting for approval; renders are under data/renders/
vicepulse decide --clip 1 --decision approve --by "your name" \
  --tiktok-options '{"privacy_level": "SELF_ONLY", "allow_comment": true, "allow_duet": false,
                     "allow_stitch": false, "consent_confirmed": true}'
vicepulse schedule && vicepulse publish   # prints dry_run: nothing is sent
vicepulse health
```

`vicepulse --help` lists every command. The n8n stack (`docker compose up`) is described at the top of
`docker-compose.yml`; it has not been run as a deployment.

## What the tests prove

`python -m pytest`, last run on 10 November 2026: **59 passed** in about 4 minutes.

- A synthetic FFmpeg clip (test patterns + tone, generated inside the tests; no video files are committed) goes
  from ingest to 1080x1920 H.264 files for all three platforms, for both EN and pt-BR, with captions burned in
  (checked by comparing pixels against a caption-free render).
- Rights gate: footage with no ledger row, an unverified licence, or an own-footage row on someone else's upload
  is quarantined and cannot be analysed, rendered or published; an expired licence blocks a post at publish time.
- Duplicate checks: an overlapping cut of the same moment, the same visuals from a re-encoded copy (perceptual
  hash), and a near-identical script are all blocked; Postgres refuses a second job for the same clip and platform.
- Nothing is scheduled without approval; with live publishing off no platform client is even built; re-running the
  publisher never posts twice; retries and hard failures behave as designed; takedown removes via API where
  possible and lists manual removals.
- The Claude client sends the agreed models, adaptive thinking, `output_config.format` JSON schemas, no
  `temperature` and no forced `tool_choice` (checked against a fake client, not the real API).
- Platform clients build the documented requests (checked against fake HTTP sessions, not the real APIs).
- All ten n8n workflows are connected, call real CLI commands, and match the generator.

## What is mocked or unverified

- **Claude:** `MockLLM` everywhere in tests. The real `ClaudeLLM` has never made a call. Prompt quality is untested.
- **YouTube, Instagram, TikTok:** clients follow the official docs read on 10 November 2026 (see `approvals/`),
  but have never sent a request. Some endpoints were not verifiable (listed in each approvals file). YouTube's
  current docs contradict PLAN.md about private-only uploads for unaudited projects; see
  `approvals/youtube-api-compliance-audit.md`.
- **Whisper:** behind an interface, optional; not installed or tested here (`VICEPULSE_TRANSCRIBER=none`).
- **docker-compose:** validated with `docker compose config`, never started. n8n image tag is `latest`; pin it.
- **n8n workflows:** structure tested; never imported into a running n8n.

## Not built yet

- Audio-fingerprint duplicate layer (PLAN.md 3.6). Time overlap, perceptual hash, text similarity and the
  unique (clip, platform) key are built.
- Moving crop: the 9:16 crop is placed once per clip where the motion is, with a blurred-fill fallback; it does
  not follow the action frame by frame.
- Caption timing from the voice recording: captions use estimated timing.
- TikTok review page parts the audit needs: creator nickname, video preview, editable caption, status polling.
- Token-expiry alerts (Instagram long-lived tokens), Metabase dashboard, the weekly Claude summary, launch-week
  faster cycle (the flag is in `config/games.json`, the schedule change is not).
- Synthetic voice (no vendor chosen or paid for).
- Brazilian Portuguese versions of the legal documents.
